Module 01

飞书接单：把非结构化订单变成草稿

目标用户是客服或销售。核心价值不是“聊天机器人”，而是把分散在群消息里的订单信息变成可确认、可转任务的数据。

客户价值

  • 减少手工抄单和漏字段。
  • 让客服确认后再进入生产任务，避免脏数据直接进入排产。
  • 保留飞书消息、草稿记录和任务记录之间的来源关系。

适合演示的话术

“客户订单可以先进入草稿，不会直接影响生产；客服确认后，才转成正式生产任务。”

Module 02

移动确认：让订单流转更轻

手机端不是完整编辑器，它适合确认订单、查看任务和施工单。客服可以在手机上完成单条确认或批量确认。

为什么要有手机端？

  • 客服不一定一直坐在电脑前。
  • 现场和管理者更需要“看结果”，而不是编辑复杂数据。
  • 手机端降低客户试用门槛，也方便演示闭环。

边界

手机端建议只做确认和查看，不做复杂装炉编辑。复杂装炉仍应在电脑 / iPad 上完成。

Module 03

电脑 / iPad 装炉设计：总工的核心工作台

这里承接生产任务、设备资源和工装规则。总工可以同步资源、导入任务、合炉设计、配置摆放规则，并生成 3D 装炉方案。

资源同步

同步设备、工装和生产任务，保证装炉计算使用的是当前可用资源。

合炉设计

按照质量、交付、成本策略形成合炉组合，也支持人工拼炉。

摆放规则

配置空间利用、承重安全、分层算法、立放等规则，保留总工判断。

Module 04

方案输出：JSON、方案库与现场施工单

方案不能只停留在 3D 页面里。真正有价值的是保存完整方案 JSON、生成施工单、写回飞书方案记录，并支持后续恢复 3D 和历史复用。

输出结果

  • 方案链接：电脑端可打开并恢复 3D。
  • PDF / 施工单链接：手机和现场可查看。
  • 方案 JSON：用于回存、导入、历史复用。

管理价值

过去“这一炉怎么装的”只能问人；现在可以从方案记录表查回方案、施工单和对应生产任务。

FAQ

客户会问什么，我们怎么回答

这会不会替代总工？

不会。正确定位是 AI 出初稿、总工做确认、现场按施工单执行。系统帮助沉淀经验，不替代工艺判断。

会不会和 ERP / MES 冲突？

第一阶段不替代 ERP/MES。它更像装炉决策与施工单生成层，接收订单/生产任务，输出装炉方案和现场施工单。

为什么不用设备厂商系统做？

设备厂商系统更关注炉温曲线、PLC、真空度、报警等设备运行；本系统关注“这批工件怎么合炉、怎么摆、怎么下达到现场”。

第一期最适合从哪里试点？

建议从重复订单较多、总工经验依赖明显、现场摆放容易出错的车间开始。先跑通订单到施工单闭环，再逐步接入历史质量结果。

建议演示顺序

先从飞书群里的一条订单开始，展示草稿、确认、生产任务、装炉设计、方案输出和手机施工单。客户更容易理解这是一个业务闭环，而不是孤立 3D 工具。
